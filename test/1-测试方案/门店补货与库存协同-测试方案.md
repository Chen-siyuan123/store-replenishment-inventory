## 2. 场景设计依据

测试设计直接对应系统的四道防线，每条防线都有至少一个场景族验证其"不可绕过"：

1. **数量防线**（框架层正则独立抽取，模型改不动）→ S1-12、S3-08（改口话术取第一处明确数量）、S3-09（无法解析即拒答不瞎猜）；
2. **写操作门禁**（validate 四项校验签发一次性令牌 → 令牌内容与申请一致 → 建草稿前 HITL 人工确认）→ S1-04/05、S2-01~12、S3-01/02/03/04/12、S4-09；
3. **检索防硬答**（BM25+向量两级门禁，相关度不达标直接回答「制度中未找到」）→ S1-08/09、S3-10/11；
4. **业务停止条件**（六类 `blocking=true` + 自动转交单）→ S5-01~06。

用例数据全部来自种子业务数据中的 6 个典型 SKU（A001 正常 / A002 促销期牛奶 / A003 零销量+促销 / A004 账实不一致 / A005 新品无历史+旧编码 / A006 对照），与 `docs/requirements/拾光连锁-业务需求发现报告.md` 的 f 编号事实一一对应。

- **环境**：Windows 11 + Python 3.13；种子数据由 `db.py` 自动生成（6 SKU / 库存快照 / 30 天销量 / 促销窗口 / 配送线路 / 预置账号）；知识库由 `prototype/data/补货制度.md` 自动导入建索引。
